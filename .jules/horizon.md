## 2025-03-09 — Cryptographic Hash Migration (SHA-256)
**Risk identified:** The legacy `generateAuditHash` relies on simple string concatenation with delimiters (`|`) and a naive 32-bit integer custom hashing algorithm. This pattern is vulnerable to delimiter injection and provides no real cryptographic security or collision resistance, making the audit trail easily forgeable.
**Migration target:** The ecosystem standard for secure, append-only logs is cryptographic hashing (SHA-256) combined with structured serialization (JSON stringify) to prevent manipulation. Schema versioning is necessary to transition chains without breaking backward compatibility.
**Migrated this session:** Added `generateAuditHashV2` implementing SHA-256 via Web Crypto API with structured JSON serialization. Preserved legacy `generateAuditHash` and `createAuditLog` for backward compatibility, adhering to an additive migration strategy. Added `createAuditLogV2` to asynchronously generate V2 hashes and explicitly tag logs with `hashVersion: 2`. Updated TypeScript definitions (`AuditTrail`) to support optional schema versions.
**Remaining:** Migrate all existing consumers of `createAuditLog` to `await createAuditLogV2`, then deprecate and remove the V1 synchronous functions. Evaluate building a mechanism to detect chain tampering and explicitly render the `hashVersion` UI.
**Next session:** Identify call-sites for the audit log, update them to the new asynchronous API, and ensure the frontend/UI logic gracefully handles V2 logs.
