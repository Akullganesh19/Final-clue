## 2026-07-12 — Migrate audit logs to secure SHA-256 hashing
**Risk identified:** The legacy `generateAuditHash` function used a custom, 32-bit bitwise integer hashing algorithm (`hash = (hash << 5) - hash + char`). This is fundamentally weak against collisions and exposes the audit trail to delimiter injection attacks because it used manual string concatenation (`${previousHash}|${action}|...`). This makes the critical audit ledger non-compliant with standard security guarantees and easily compromised if attackers can forge audit actions.
**Migration target:** Modern, asynchronous Web Crypto API (`crypto.subtle.digest('SHA-256')`) using `JSON.stringify` to securely structure multiple parameters into a byte stream, removing ambiguity and delimiter injection risks.
**Migrated this session:** Created new async versions (`generateAuditHashAsync` and `createAuditLogAsync`) in `src/utils/audit.ts`. Marked the synchronous versions as `@deprecated`. Preserved the full 64-character hex signature of SHA-256 output (plus prefix) to ensure collision resistance.
**Remaining:** Migrate components to use the new async audit log functions instead of the deprecated synchronous ones. Refactor related UI logic to handle async operations where necessary.
**Next session:** Start migrating call sites of `createAuditLog` to `createAuditLogAsync`, beginning with core state changes and working outwards to UI event handlers.
